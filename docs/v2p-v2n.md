# 9단계: V2P(보행자)와 V2N(교통센터) 추가

8단계까지는 차 ↔ RSU(V2I)만 실제로 쓰였다. 이 단계에서 **보행자 스마트폰(V2P)** 과 **교통센터(V2N)** 를 더했다.
모든 메시지는 지금까지처럼 OpenSCMS가 발급한 인증서로 IEEE 1609.2 서명하고, 받는 쪽은 같은 4단계로 검증한다.

## 구성

| 장치 | 프로그램 | 인증서 (OpenSCMS) | 하는 일 |
| --- | --- | --- | --- |
| 보행자 스마트폰 PED-01 | `ped/ped.py` | 휴대 단말(OBU 종류), PSM 0x27 | 각본대로 걸으며 0.1초마다 PSM을 서명해 직접 방송 |
| 교통센터 TMC-01 | `center/center.py` | 인프라(RSU 종류), TIM 0x8003 | 휴대폰망(TLS 1.3)으로 차의 위치 보고를 받고, 공사 구간 안내 TIM을 내려보냄. 같은 TIM을 RSU에도 넘김 |
| OBU | `obu/obu.py` (수정) | BSM 0x20 | PSM·TIM 검증과 반영, 휴대폰망 접속, 1초마다 BSM 위치 보고 |
| RSU 게이트웨이 | `rsu-gateway/gateway.py` (수정) | — | BSM에 더해 PSM도 검증해서 V2X-Hub로 |
| RSU 서명기 | `rsu-signer/signer.py` (수정) | — | 센터가 서명한 TIM(UDP 1517)을 서명 확인 후 그대로 방송 |

## 시나리오

1. **V2P 무단횡단**: 10초에 보행자가 교차로 동쪽 40 m 지점에서 횡단보도가 아닌 곳으로 도로를 건넌다. 서→동 차(OBU-01)는 초록불에 교차로를 지나며 PSM을 보고, 보행자가 앞길 위에 있거나 2초 안에 들어올 것 같으면 보행자 4 m 앞에 선다. 보행자가 다 건너면 출발한다.
   - SUMO 화면에서 보행자는 노란 점(POI)이다. SUMO의 차는 POI를 보지 못하므로, "건물이나 주차된 차에 가려 운전자가 못 보는 보행자" 상황이다. 차가 서는 것은 V2P 메시지 덕분이다.
   - 협력주행을 끄면(`bash scripts/run.sh`) 차는 그대로 지나가고, 보행자 화면에 `위험! obu1가 0.7m 거리로 지나감`이 찍힌다.
2. **V2N 공사 구간**: 교통센터가 교차로 북쪽 70 m(반지름 40 m)를 공사 구간으로, 권고 속도 30 km/h로 안내한다. 남→북 차(OBU-02)는 신호를 받고 출발한 뒤 이 구간에서 30 km/h로 줄인다. 안내는 휴대폰망과 RSU 두 경로로 오고, 화면에 `받은 경로 V2N+V2X`로 보인다.
3. **V2N 위치 보고**: 두 차가 1초마다 휴대폰망으로 서명된 BSM을 올리고, 센터는 검증 후 `logs/center.out`에 차량 수와 속도를 보여 준다.

## 표준을 어떻게 골랐나 (감안한 점)

팀 자료("V2V·V2P·V2N 통신 보안 요구사항", "미국·유럽·한국 V2X 통신 보안 표준 비교")를 기준으로 했다.
자료에 정해진 것은 그대로 따르고, 국내 자료에 없는 것은 아래처럼 정했다.

| 정할 것 | 자료에 있나 | 이 환경의 선택 | 이유 |
| --- | --- | --- | --- |
| 보행자 메시지 | 있음: PSM, KS R 1600-6 | J2735 PSM (메시지 번호 32) | 국내 메시지 이름과 같음 |
| 보행자 PSID | 있음: 0x27 | 0x27 | IEEE PSID 등록부 |
| 누가 PSM을 보내나 | **국내 자료에 없음** | **보행자 단말이 직접** | 유럽 VAM은 단말만 보냄. RSU 대리 방송(V2X-Hub Pedestrian 플러그인)은 우리 V2X-Hub 8.1.0에 있는지 확인되지 않았고, 새 입력 경로(A-P2)가 생김 |
| 보행자 인증서 종류 | 자료에 없음 | OpenSCMS 장치 종류 **OBU**로 등록 | SCMS의 단말 종류는 OBE(차량·휴대 단말)와 RSE 두 가지 |
| V2N 방식 | 있음: 하이브리드 (국토부 2022.9.23) | 휴대폰망 + RSU 두 경로로 같은 TIM | 국내 방침 그대로 |
| 센터 → 차 메시지 | 자료에 KS R 1600-5(여행자 정보·노변 경고) 언급 | **TIM** (메시지 번호 31), PSID 0x8003, 내용은 도로 공사(ITIS 1025) + 권고 속도 | 공사 안내의 대표 메시지. V2X-Hub·USDOT ODE도 TIM 사용 |
| 차 → 센터 메시지 | 자료에 KS R 1600-4(프로브) 언급 | **서명된 BSM**을 1초마다 | 하이브리드 방식은 같은 메시지를 여러 경로로 보내는 것. 프로브 메시지는 2차 확장 |
| 휴대폰망에서도 서명? | **국내 자료에 없음** | **유지** (V2X와 같은 4단계 검증) | 유럽 5GAA Uu 프로파일은 항상 서명. A-N3(경로별 동일 검증) 요구와 같음 |
| 센터 통신 보호 | 있음: TLS 보안 채널 (TTAK.KO-12.0432) | **TLS 1.3**, 시험용 TLS CA로 센터 인증서 발급, 1.2 이하 거부 | 미국 CTI 4001은 TLS 1.3 |
| 센터 → RSU 전달 | 자료: RSU가 대신 서명(CTI 4001) | 센터가 서명한 것을 **RSU가 확인만 하고 그대로** 방송 | 출처 서명을 보존 (CTI 4001: 원 출처가 서명한 메시지는 그대로 전달) |
| OpenSCMS 권한 정책 | — | OBU 종류: BSM·PSM, RSU 종류: SPaT·MAP·TIM | `openscms-patch/psid-policy-v2p-v2n.patch` |

## 팀 보안 요구사항과의 관계

| 요구사항 | 이 단계에서 |
| --- | --- |
| A-P1 보행자 메시지 PSID 검증 | 반영됨: 차량 인증서(BSM)로 서명한 가짜 PSM은 `NO_PERMISSION`으로 거부 |
| A-N2 인증 통신 보호(TLS) | 교통센터 통신에 TLS 1.3 적용. OpenSCMS 통신은 아직 HTTP |
| A-N3 다중 경로 동일 검증 | 반영됨: 휴대폰망과 RSU 경로 모두 같은 4단계 검증. RSU에 넘긴 가짜 TIM도 서명기에서 거부 |
| A-P2 RSU 대리 PSM 입력 검증 | 해당 없음 (RSU 대리 방송을 쓰지 않음) |
| A-P3 보행자 위치 프라이버시 | 아직 없음: 보행자 임시 ID와 인증서가 고정 |
| A-V1~V3 | 아직 없음 (차는 다른 차의 BSM을 쓰지 않음) |

시험으로 확인한 것 (OpenSCMS C 코덱으로 만든 시험 서버 + SUMO 화면 없이):
- 협력주행: OBU-01이 보행자 4 m 앞에서 정지 후 재출발, OBU-02가 공사 구간에서 8.33 m/s(30 km/h)
- 협력주행 끔: OBU-01이 13.9 m/s로 보행자 0.7 m 옆을 지나감
- 거부: 차량 인증서로 만든 PSM, RSU·보행자 인증서로 만든 TIM → `NO_PERMISSION`. 보행자 인증서로 만든 BSM을 휴대폰망으로 올림 → 센터가 거부
- TLS: 다른 CA로 센터를 확인하면 연결 실패, TLS 1.2로 접속하면 거부
- 전체 실행에서 거부 0건 (정상 메시지는 모두 통과)

## 처음 설정 (OpenSCMS 권한 정책)

OpenSCMS RA는 장치 종류별로 허용된 PSID만 발급한다. 보행자(PSM)와 교통센터(TIM)를 허용하도록 정책을 바꾼다.

```bash
bash ~/v2x-kr-testbed/openscms-patch/apply.sh
cd ~/openscms/OpenSCMS && skaffold run
kubectl rollout restart deployment/ra-deployment
kubectl get pods            # ra-deployment가 다시 Running 1/1 이 될 때까지 1분쯤
cd ~/v2x-kr-testbed && python3 scripts/provision.py
```

`provision.py`에서 `PED-01 ... PSID ['0x27']`, `TMC-01 ... PSID ['0x8003']`가 나오면 된다.
(정책만 바뀌었으므로 Rust 빌드는 다시 하지 않는다. RA가 설정을 다시 읽도록 재시작만 한다.)

## 단순화한 점

- 보행자는 1명이고 각본대로 움직인다. SUMO 보행자 모델(보도·횡단보도)은 쓰지 않았다. 도로망을 바꾸면 MAP·신호 번호가 바뀌기 때문이다.
- 휴대폰망은 내 PC 안의 TCP 연결이다. 지연·끊김은 흉내 내지 않는다.
- 교통센터 → RSU 구간은 UDP(보호 없음)다. 서명 확인으로 내용은 지키지만 전송 구간 TLS는 2차 과제(A-4, SR-A-03).
- 교통센터의 공사 안내는 고정된 1건이다. 받은 위치 보고는 모으기만 하고 판단에 쓰지 않는다.
- TIM의 권고 속도는 글자 항목(`"30 km/h"`)으로 넣었다. 정식으로는 경로 속성(speedLimits)에 넣는다.
